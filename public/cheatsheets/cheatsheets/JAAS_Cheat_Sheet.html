    JAAS Cheat Sheet¶

    Введение — что такое аутентификация JAAS¶

    Процесс проверки личности пользователя или другой системы называется аутентификацией.

    JAAS — фреймворк аутентификации, управляющий идентификационными данными и учётными данными аутентифицированного пользователя от входа до выхода.

    Жизненный цикл аутентификации JAAS:

    1. Создать LoginContext.
    2. Прочитать файл конфигурации для инициализации одного или нескольких LoginModule.
    3. Вызвать LoginContext.initialize() для каждого LoginModule.
    4. Вызвать LoginContext.login() для каждого LoginModule.
    5. Если вход выполнен успешно — вызвать LoginContext.commit(), иначе — LoginContext.abort()

    Файл конфигурации¶

    Файл конфигурации JAAS содержит блок LoginModule для каждого доступного LoginModule, предназначенного для входа в приложение.

    Пример блока из файла конфигурации JAAS:

    Branches
{
    USNavy.AppLoginModule required
    debug=true
    succeeded=true;
}

    Обратите внимание на расстановку точек с запятой — они завершают как записи LoginModule, так и сами блоки.

    Слово required означает, что метод login() объекта LoginContext должен завершиться успешно при входе пользователя. Параметры debug и succeeded, специфичные для LoginModule, передаются в LoginModule.

    Они определяются LoginModule, и их использование управляется внутри LoginModule. Обратите внимание: параметры конфигурируются в виде пар «ключ-значение», например debug="true", а ключ и значение разделяются знаком =.

    Main.java (клиент)¶

    • Синтаксис запуска:
    Java –Djava.security.auth.login.config==packageName/packageName.config
        packageName.Main Stanza1

Где:
    packageName — директория, содержащая файл конфигурации.
    packageName.config — указывает файл конфигурации в Java-пакете packageName.
    packageName.Main — указывает Main.java в Java-пакете packageName.
    Stanza1 — имя блока, который Main() должен прочитать из файла конфигурации.
    • При запуске первый аргумент командной строки — это имя блока из файла конфигурации. Блок задаёт используемый LoginModule. Второй аргумент — это CallbackHandler.
    • Создать новый LoginContext с аргументами, переданными в Main.java.
      • loginContext = new LoginContext (args[0], new AppCallbackHandler());
    • Вызвать LoginModule через LoginContext:
      • loginContext.login();
    • Значение из параметра succeeded возвращается из loginContext.login().
    • При успешном входе создаётся объект subject.

    LoginModule.java¶

    LoginModule должен содержать следующие методы аутентификации:

    • initialize()
    • login()
    • commit()
    • abort()
    • logout()

    initialize()¶

    В Main(), после того как LoginContext прочитал нужный блок из файла конфигурации, LoginContext инстанциирует LoginModule, указанный в блоке.

    • Сигнатура метода initialize():
      • Public void initialize (Subject subject, CallbackHandler callbackHandler, Map sharedState, Map options)
    • Переданные аргументы следует сохранить следующим образом:
      • this.subject = subject;
      • this.callbackHandler = callbackHandler;
      • this.sharedState = sharedState;
      • this.options = options;
    • Что делает метод initialize():
      • Строит объект subject класса Subject при условии успешного выполнения login().
      • Устанавливает CallbackHandler, который взаимодействует с пользователем для получения данных входа.
      • Если LoginContext задаёт 2 или более LoginModule (что допустимо), они могут обмениваться данными через карту sharedState.
      • Сохраняет информацию о состоянии, такую как debug и succeeded, в карте options.

    login()¶

    Захватывает данные входа, предоставленные пользователем. Фрагмент кода ниже объявляет массив из двух объектов обратного вызова, которые при передаче в метод callbackHandler.handle программы callbackHandler.java будут заполнены именем пользователя и паролем, введёнными пользователем в интерактивном режиме:

    NameCallback nameCB = new NameCallback("Username");
PasswordCallback passwordCB = new PasswordCallback ("Password", false);
Callback[] callbacks = new Callback[] { nameCB, passwordCB };
callbackHandler.handle (callbacks);
    • Аутентифицирует пользователя
    • Извлекает введённые пользователем данные из объектов обратного вызова:
      • String ID = nameCallback.getName ();
      • char[] tempPW = passwordCallback.getPassword ();
    • Сравнить name и tempPW со значениями, хранящимися в репозитории, например LDAP.
    • Установить значение переменной succeeded и вернуться в Main().

    commit()¶

    После успешной проверки учётных данных пользователя в методе login() фреймворк аутентификации JAAS связывает эти учётные данные (при необходимости) с объектом subject.

    Существует два типа учётных данных — Public (публичные) и Private (приватные):

    • Публичные учётные данные включают открытые ключи.
    • Приватные учётные данные включают пароли и закрытые ключи.

    К объекту subject добавляются principals (то есть идентификаторы субъекта, отличные от имени для входа), такие как табельный номер сотрудника или идентификатор участника в группе пользователей.

    Ниже приведён пример метода commit(), в котором сначала для каждой группы, членом которой является аутентифицированный пользователь, имя группы добавляется как principal к субъекту. Затем имя пользователя добавляется в его публичные учётные данные.

    Фрагмент кода, устанавливающий и добавляющий principals и публичные учётные данные к субъекту:

    public boolean commit() {
    If (userAuthenticated) {
        Set groups = UserService.findGroups (username);
        for (Iterator itr = groups.iterator (); itr.hasNext (); {
            String groupName = (String) itr.next ();
            UserGroupPrincipal group = new UserGroupPrincipal (GroupName);
            subject.getPrincipals ().add (group);
        }
        UsernameCredential cred = new UsernameCredential (username);
        subject.getPublicCredentials().add (cred);
    }
}

    abort()¶

    Метод abort() вызывается при неудачной аутентификации. Перед выходом из LoginModule в методе abort() необходимо сбросить состояние, включая поля ввода имени пользователя и пароля.

    logout()¶

    Освобождение principals и учётных данных пользователя при вызове LoginContext.logout:

    public boolean logout() {
    if (!subject.isReadOnly()) {
        Set principals = subject.getPrincipals(UserGroupPrincipal.class);
        subject.getPrincipals().removeAll(principals);
        Set creds = subject.getPublicCredentials(UsernameCredential.class);
        subject.getPublicCredentials().removeAll(creds);
        return true;
    } else {
        return false;
    }
}

    CallbackHandler.java¶

    callbackHandler хранится в отдельном исходном файле (.java), независимом от какого-либо конкретного LoginModule, чтобы обслуживать множество LoginModule с различными объектами обратного вызова:

    • Создаёт экземпляр класса CallbackHandler и содержит единственный метод handle().
    • Пример CallbackHandler для LoginModule, требующего имя пользователя и пароль:
    public void handle(Callback[] callbacks) {
    for (int i = 0; i < callbacks.length; i++) {
        Callback callback = callbacks[i];
        if (callback instanceof NameCallback) {
            NameCallback nameCallBack = (NameCallback) callback;
            nameCallBack.setName(username);
    }  else if (callback instanceof PasswordCallback) {
            PasswordCallback passwordCallBack = (PasswordCallback) callback;
            passwordCallBack.setPassword(password.toCharArray());
        }
    }
}
