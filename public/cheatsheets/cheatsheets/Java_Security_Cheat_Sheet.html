    Java Security Cheat Sheet¶

    Предотвращение инъекций в Java¶

    Этот раздел содержит рекомендации по обработке инъекций в коде Java-приложений.

    Примеры кода из рекомендаций размещены здесь.

    Что такое инъекция¶

    Инъекция по версии OWASP Top 10 определяется следующим образом:

    Рассматривайте любого, кто может отправить системе недоверенные данные: внешних пользователей, внутренних пользователей и администраторов.

    Общие рекомендации по предотвращению инъекций¶

    Следующий подход можно применить в общем случае для предотвращения проблем с инъекцией:

    1. Применять валидацию входных данных (используя подход с белым списком) в сочетании с очисткой и экранированием выходных данных для пользовательского ввода/вывода.
    2. Если необходимо взаимодействовать с системой, старайтесь использовать возможности API, предоставляемые вашим технологическим стеком (Java / .Net / PHP...), вместо того чтобы строить команды вручную.

    Дополнительные рекомендации приведены в этом cheatsheet.

    Конкретные типы инъекций¶

    Примеры в этом разделе написаны на Java (см. связанный Maven-проект), но рекомендации применимы и к другим технологиям: .Net / PHP / Ruby / Python...

    SQL¶

    Симптом¶

    Инъекция этого типа происходит, когда приложение использует недоверенный пользовательский ввод для формирования SQL-запроса в виде строки и его выполнения.

    Как предотвратить¶

    Используйте параметризацию запросов для предотвращения инъекции.

    Пример¶

    /*Здесь не используется DB-фреймворк, чтобы показать реальное применение
  Prepared Statement из Java API*/
/*Открыть соединение с базой данных H2 и использовать его*/
Class.forName("org.h2.Driver");
String jdbcUrl = "jdbc:h2:file:" + new File(".").getAbsolutePath() + "/target/db";
try (Connection con = DriverManager.getConnection(jdbcUrl)) {

    /* Пример A: Выборка данных с использованием Prepared Statement*/
    String query = "select * from color where friendly_name = ?";
    List<String> colors = new ArrayList<>();
    try (PreparedStatement pStatement = con.prepareStatement(query)) {
        pStatement.setString(1, "yellow");
        try (ResultSet rSet = pStatement.executeQuery()) {
            while (rSet.next()) {
                colors.add(rSet.getString(1));
            }
        }
    }

    /* Пример B: Вставка данных с использованием Prepared Statement*/
    query = "insert into color(friendly_name, red, green, blue) values(?, ?, ?, ?)";
    int insertedRecordCount;
    try (PreparedStatement pStatement = con.prepareStatement(query)) {
        pStatement.setString(1, "orange");
        pStatement.setInt(2, 239);
        pStatement.setInt(3, 125);
        pStatement.setInt(4, 11);
        insertedRecordCount = pStatement.executeUpdate();
    }

   /* Пример C: Обновление данных с использованием Prepared Statement*/
    query = "update color set blue = ? where friendly_name = ?";
    int updatedRecordCount;
    try (PreparedStatement pStatement = con.prepareStatement(query)) {
        pStatement.setInt(1, 10);
        pStatement.setString(2, "orange");
        updatedRecordCount = pStatement.executeUpdate();
    }

   /* Пример D: Удаление данных с использованием Prepared Statement*/
    query = "delete from color where friendly_name = ?";
    int deletedRecordCount;
    try (PreparedStatement pStatement = con.prepareStatement(query)) {
        pStatement.setString(1, "orange");
        deletedRecordCount = pStatement.executeUpdate();
    }

}

    JPA¶

    Симптом¶

    Инъекция этого типа происходит, когда приложение использует недоверенный пользовательский ввод для формирования JPA-запроса в виде строки и его выполнения. Это похоже на SQL-инъекцию, но изменяемый язык здесь — не SQL, а JPA QL.

    Как предотвратить¶

    Используйте параметризацию запросов на языке Java Persistence Query Language для предотвращения инъекции.

    Пример¶

    EntityManager entityManager = null;
try {
    /* Получить ссылку на EntityManager для доступа к БД */
    entityManager = Persistence.createEntityManagerFactory("testJPA").createEntityManager();

    /* Определить прототип параметризованного запроса с именованным параметром для улучшения читаемости */
    String queryPrototype = "select c from Color c where c.friendlyName = :colorName";

    /* Создать запрос, задать именованный параметр и выполнить запрос */
    Query queryObject = entityManager.createQuery(queryPrototype);
    Color c = (Color) queryObject.setParameter("colorName", "yellow").getSingleResult();

} finally {
    if (entityManager != null && entityManager.isOpen()) {
        entityManager.close();
    }
}

    XML: XPath-инъекция¶

    Симптом¶

    Инъекция этого типа происходит, когда приложение использует недоверенный пользовательский ввод для формирования XPath-запроса в виде строки и его выполнения.

    Как предотвратить¶

    Используйте XPath Variable Resolver для предотвращения инъекции.

    Пример¶

    Реализация Variable Resolver.

    /**
 * Резолвер для определения параметров XPATH-выражения.
 *
 */
public class SimpleVariableResolver implements XPathVariableResolver {

    private final Map<QName, Object> vars = new HashMap<QName, Object>();

    /**
     * Внешний метод для добавления параметра
     *
     * @param name Имя параметра
     * @param value Значение параметра
     */
    public void addVariable(QName name, Object value) {
        vars.put(name, value);
    }

    /**
     * {@inheritDoc}
     *
     * @see javax.xml.xpath.XPathVariableResolver#resolveVariable(javax.xml.namespace.QName)
     */
    public Object resolveVariable(QName variableName) {
        return vars.get(variableName);
    }
}

    Код, использующий резолвер для выполнения XPath-запроса.

    /*Создать фабрику построителя XML-документов*/
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();

/*Отключить разрешение внешних сущностей для различных случаев*/
//Здесь не выполняется, чтобы сосредоточиться на коде резолвера переменных
//Но выполняйте это в продуктивном коде!

/*Загрузить XML-файл*/
DocumentBuilder builder = dbf.newDocumentBuilder();
Document doc = builder.parse(new File("src/test/resources/SampleXPath.xml"));

/* Создать и настроить резолвер параметров */
String bid = "bk102";
SimpleVariableResolver variableResolver = new SimpleVariableResolver();
variableResolver.addVariable(new QName("bookId"), bid);

/*Создать и настроить XPATH-выражение*/
XPath xpath = XPathFactory.newInstance().newXPath();
xpath.setXPathVariableResolver(variableResolver);
XPathExpression xPathExpression = xpath.compile("//book[@id=$bookId]");

/* Применить выражение к XML-документу */
Object nodes = xPathExpression.evaluate(doc, XPathConstants.NODESET);
NodeList nodesList = (NodeList) nodes;
Element book = (Element)nodesList.item(0);
var containsRalls = book.getTextContent().contains("Ralls, Kim");

    HTML/JavaScript/CSS¶

    Симптом¶

    Инъекция этого типа происходит, когда приложение использует недоверенный пользовательский ввод для формирования HTTP-ответа и отправки его в браузер.

    Как предотвратить¶

    Применяйте строгую валидацию входных данных (подход с белым списком) или, если валидация невозможна, используйте очистку и экранирование выходных данных (по возможности совмещайте оба подхода).

    Пример¶

    /*
ВХОДНЫЕ ДАННЫЕ: получение данных от пользователя
Здесь рекомендуется использовать строгую валидацию входных данных с подходом на основе белого списка.
По сути, вы гарантируете, что во входных данных содержатся только допустимые символы.
*/

String userInput = "You user login is owasp-user01";

/* Сначала проверяем, что значение содержит только ожидаемые символы*/
if (!Pattern.matches("[a-zA-Z0-9\\s\\-]{1,50}", userInput))
{
    return false;
}

/* Если первая проверка пройдена, убеждаемся, что потенциально опасные символы,
которые мы разрешили по бизнес-требованиям, не используются опасным образом.
Например, мы разрешили символ '-', который может использоваться в SQL-инъекции,
поэтому убеждаемся, что он не используется в последовательной форме.
Используем API COMMONS LANG v3 для анализа строк...
*/
If (0 != StringUtils.countMatches(userInput.replace(" ", ""), "--"))
{
    return false;
}

/*
ВЫХОДНЫЕ ДАННЫЕ: отправка данных пользователю
Здесь мы экранируем и очищаем все данные, отправляемые пользователю
Используем OWASP Java HTML Sanitizer API для очистки
Используем OWASP Java Encoder API для кодирования HTML-тегов (экранирования)
*/

String outputToUser = "You <p>user login</p> is <strong>owasp-user01</strong>";
outputToUser += "<script>alert(22);</script><img src='#' onload='javascript:alert(23);'>";

/* Создать политику очистки, разрешающую только теги '<p>' и '<strong>'*/
PolicyFactory policy = new HtmlPolicyBuilder().allowElements("p", "strong").toFactory();

/* Очистить выходные данные, которые будут отправлены пользователю*/
String safeOutput = policy.sanitize(outputToUser);

/* Кодировать HTML-теги*/
safeOutput = Encode.forHtml(safeOutput);
String finalSafeOutputExpected = "You <p>user login</p> is <strong>owasp-user01</strong>";
if (!finalSafeOutputExpected.equals(safeOutput))
{
    return false;
}

    NoSQL¶

    Симптом¶

    Инъекция этого типа происходит, когда приложение использует недоверенный пользовательский ввод для формирования выражения вызова NoSQL API.

    Как предотвратить¶

    Поскольку существует много NoSQL-СУБД и каждая из них использует свой API для вызовов, важно убедиться, что пользовательский ввод, используемый для формирования выражения вызова API, не содержит символов, имеющих специальное значение в синтаксисе целевого API. Это нужно для предотвращения выхода за рамки исходного выражения и создания нового на основе введённых пользователем данных. Также важно не использовать конкатенацию строк для построения выражений вызова API — используйте API для создания выражений.

    Пример — MongoDB¶

     /* Здесь в качестве целевой NoSQL БД используется MongoDB */
String userInput = "Brooklyn";

/* Сначала убеждаемся, что входные данные не содержат специальных символов
для текущего API вызова NoSQL БД,
здесь это: ' " \ ; { } $
*/
//На этот раз избегаем regexp, чтобы сделать код валидации
//более понятным и читаемым...
ArrayList < String > specialCharsList = new ArrayList < String > () {
    {
        add("'");
        add("\"");
        add("\\");
        add(";");
        add("{");
        add("}");
        add("$");
    }
};

for (String specChar: specialCharsList) {
    if (userInput.contains(specChar)) {
        return false;
    }
}

//Также проверяем максимальный размер входных данных
if (!userInput.length() <= 50)
{
    return false;
}

/* Затем выполняем запрос к базе данных, используя API для построения выражения */
//Подключиться к локальному экземпляру MongoDB
try(MongoClient mongoClient = new MongoClient()){
    MongoDatabase db = mongoClient.getDatabase("test");
    //Использовать построитель запросов API для создания выражения вызова
    //Создать выражение
    Bson expression = eq("borough", userInput);
    //Выполнить вызов
    FindIterable<org.bson.Document> restaurants = db.getCollection("restaurants").find(expression);
    //Проверить согласованность результата
    restaurants.forEach(new Block<org.bson.Document>() {
        @Override
        public void apply(final org.bson.Document doc) {
            String restBorough = (String)doc.get("borough");
            if (!"Brooklyn".equals(restBorough))
            {
                return false;
            }
        }
    });
}

    Log Injection¶

    Симптом¶

    Log Injection возникает, когда приложение включает недоверенные данные в сообщение журнала (например, злоумышленник может создать дополнительную запись в журнале, выглядящую как запись от другого пользователя, если ему удастся внедрить символы CRLF в недоверенные данные). Подробнее об этой атаке рассказывается на странице OWASP Log Injection.

    Как предотвратить¶

    Для предотвращения записи злоумышленником вредоносного содержимого в журнал приложения применяйте следующие меры защиты:

    • Используйте структурированные форматы журналов, например JSON, вместо неструктурированных текстовых форматов. Неструктурированные форматы уязвимы к инъекции Carriage Return (CR) и Line Feed (LF) (см. CWE-93).
    • Ограничивайте размер пользовательского ввода, используемого для создания сообщения журнала.
    • Убедитесь, что все средства защиты от XSS применяются при просмотре файлов журналов в веб-браузере.

    Пример с использованием Log4j Core 2¶

    Рекомендуемая политика логирования для продуктивной среды — отправка журналов на сетевой сокет с использованием структурированного JSON Template Layout, представленного в Log4j 2.14.0, с ограничением размера строк до 500 байт с помощью атрибута конфигурации maxStringLength:

    Криптография¶

    Общие рекомендации по криптографии¶

    • Никогда и ни при каких обстоятельствах не пишите собственные криптографические функции.
    • По возможности старайтесь вообще не писать никакого криптографического кода. Вместо этого используйте готовые решения для управления секретами или решения, предоставляемые вашим облачным провайдером. Подробнее см. OWASP Secrets Management Cheat Sheet.
    • Если готовое решение для управления секретами использовать невозможно, используйте надёжную и широко известную библиотеку вместо встроенных классов JCA/JCE — последние слишком легко позволяют допустить криптографические ошибки.
    • Убедитесь, что ваше приложение или протокол может легко поддерживать будущую замену криптографических алгоритмов.
    • Используйте менеджер пакетов для поддержания всех зависимостей в актуальном состоянии. Следите за обновлениями среды разработки и планируйте обновление приложений соответствующим образом.
    • Ниже будут приведены примеры на основе Google Tink — библиотеки, созданной экспертами в области криптографии для безопасного использования криптографии (в смысле минимизации типичных ошибок при работе со стандартными криптографическими библиотеками).

class AesGcmSimple {

    public static byte[] encrypt(String plaintext, String metadata, KeysetHandle handle) throws Exception {
        // Получить примитив.
        Aead aead = handle.getPrimitive(Aead.class);
        return aead.encrypt(plaintext.getBytes(UTF_8), metadata.getBytes(UTF_8));
    }

    public static String decrypt(byte[] ciphertext, String metadata, KeysetHandle handle) throws Exception {
        // Получить примитив.
        Aead aead = handle.getPrimitive(Aead.class);
        return new String(aead.decrypt(ciphertext, metadata.getBytes(UTF_8)),UTF_8);
    }

    Симметричный пример с использованием встроенных классов JCA/JCE¶

    Если использовать отдельную библиотеку категорически невозможно, можно использовать встроенные классы JCA/JCE, однако настоятельно рекомендуется привлечь эксперта по криптографии для проверки всего дизайна и кода, поскольку даже самая незначительная ошибка может серьёзно ослабить шифрование.

    Следующий фрагмент кода демонстрирует пример использования AES-GCM для шифрования/расшифрования данных.

    Несколько ограничений и подводных камней этого кода:

    • В нём не учитываются ротация и управление ключами — это отдельная тема.
    • Важно использовать разные nonce для каждой операции шифрования, особенно если используется один и тот же ключ. Подробнее см. этот ответ на Cryptography Stack Exchange.
    • Ключ необходимо хранить в надёжном месте.
    Нажмите, чтобы увидеть фрагмент кода "JCA/JCE symmetric encryption". 
    import java.nio.charset.StandardCharsets;
import java.security.SecureRandom;
import javax.crypto.spec.*;
import javax.crypto.*;
import java.util.Base64;


// AesGcmSimpleTest
class Main {

    public static void main(String[] args) throws Exception {
        // Ключ длиной 32 байта / 256 бит для AES
        KeyGenerator keyGen = KeyGenerator.getInstance(AesGcmSimple.ALGORITHM);
        keyGen.init(AesGcmSimple.KEY_SIZE, new SecureRandom());
        SecretKey secretKey = keyGen.generateKey();

        // Nonce длиной 12 байт / 96 бит — этот размер всегда должен использоваться.
        // Крайне важно для AES-GCM использовать уникальный nonce для каждой криптографической операции.
        byte[] nonce = new byte[AesGcmSimple.IV_LENGTH];
        SecureRandom random = new SecureRandom();
        random.nextBytes(nonce);

        var message = "This message to be encrypted";
        System.out.println(message);

        // Зашифровать сообщение
        byte[] cipherText = AesGcmSimple.encrypt(message, nonce, secretKey);
        System.out.println(Base64.getEncoder().encodeToString(cipherText));

        // Расшифровать сообщение
        var message2 = AesGcmSimple.decrypt(cipherText, nonce, secretKey);
        System.out.println(message2);
    }
}

class AesGcmSimple {

    public static final String ALGORITHM = "AES";
    public static final String CIPHER_ALGORITHM = "AES/GCM/NoPadding";
    public static final int KEY_SIZE = 256;
    public static final int TAG_LENGTH = 128;
    public static final int IV_LENGTH = 12;

    public static byte[] encrypt(String plaintext, byte[] nonce, SecretKey secretKey) throws Exception {
        return cryptoOperation(plaintext.getBytes(StandardCharsets.UTF_8), nonce, secretKey, Cipher.ENCRYPT_MODE);
    }

    public static String decrypt(byte[] ciphertext, byte[] nonce, SecretKey secretKey) throws Exception {
        return new String(cryptoOperation(ciphertext, nonce, secretKey, Cipher.DECRYPT_MODE), StandardCharsets.UTF_8);
    }

    private static byte[] cryptoOperation(byte[] text, byte[] nonce, SecretKey secretKey, int mode) throws Exception {
        Cipher cipher = Cipher.getInstance(CIPHER_ALGORITHM);
        GCMParameterSpec gcmParameterSpec = new GCMParameterSpec(TAG_LENGTH, nonce);
        cipher.init(mode, secretKey, gcmParameterSpec);
        return cipher.doFinal(text);
    }

}

    Асимметричный пример с использованием Google Tink¶

    Google Tink предоставляет документацию по выполнению типовых задач.

    Например, эта страница (на сайте Google) демонстрирует, как выполнить гибридное шифрование, когда две стороны хотят обмениваться данными на основе своих асимметричных ключей.

    Следующий фрагмент кода показывает, как эта функциональность может быть использована для обмена секретами между Алисой и Бобом:

import com.google.crypto.tink.HybridEncrypt;
import com.google.crypto.tink.InsecureSecretKeyAccess;
import com.google.crypto.tink.KeysetHandle;
import com.google.crypto.tink.TinkJsonProtoKeysetFormat;
import com.google.crypto.tink.hybrid.HybridConfig;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Base64;

// HybridReplaceTest
class App {
    public static void main(String[] args) throws Exception {

        --out-format JSON --out bob_private_keyset.json

        ./tinkey create-public-keyset --in alice_private_keyset.json \
        --in-format JSON --out-format JSON --out alice_public_keyset.json

        ./tinkey create-public-keyset --in bob_private_keyset.json \
        --in-format JSON --out-format JSON --out bob_public_keyset.json
        */

        HybridConfig.register();

        // Сгенерировать пару ключей ECC для Алисы
        var alice = new HybridSimple(
                getKeysetHandle("/home/alicesmith/private_keyset.json"),
                getKeysetHandle("/home/alicesmith/public_keyset.json")

        );

        KeysetHandle alicePublicKey = alice.getPublicKey();

        // Сгенерировать пару ключей ECC для Боба
        var bob = new HybridSimple(
                getKeysetHandle("/home/bobjones/private_keyset.json"),
                getKeysetHandle("/home/bobjones/public_keyset.json")

        );

        KeysetHandle bobPublicKey = bob.getPublicKey();

        // Эту генерацию ключевой пары следует периодически повторять, чтобы
        // получить новый общий секрет и избежать долгоживущего общего секрета.

        // Алиса шифрует сообщение для отправки Бобу
        String plaintext = "Hello, Bob!";

        // Добавить релевантный контекст о зашифрованных данных, который должен быть проверен
        // при расшифровке
        String metadata = "Sender: alicesmith@example.com";

        System.out.println("Secret being sent from Alice to Bob: " + plaintext);
        var cipherText = alice.encrypt(bobPublicKey, plaintext, metadata);
        System.out.println("Ciphertext being sent from Alice to Bob: " + Base64.getEncoder().encodeToString(cipherText));


        // Боб расшифровывает сообщение
        var decrypted = bob.decrypt(cipherText, metadata);
        System.out.println("Secret received by Bob from Alice: " + decrypted);
        System.out.println();

        // Боб шифрует сообщение для отправки Алисе
        String plaintext2 = "Hello, Alice!";

        // Добавить релевантный контекст о зашифрованных данных, который должен быть проверен
        // при расшифровке
        String metadata2 = "Sender: bobjones@example.com";

        System.out.println("Secret being sent from Bob to Alice: " + plaintext2);
        var cipherText2 = bob.encrypt(alicePublicKey, plaintext2, metadata2);
        System.out.println("Ciphertext being sent from Bob to Alice: " + Base64.getEncoder().encodeToString(cipherText2));

        // Алиса расшифровывает сообщение
        var decrypted2 = alice.decrypt(cipherText2, metadata2);
        System.out.println("Secret received by Alice from Bob: " + decrypted2);

    private static KeysetHandle getKeysetHandle(String filename) throws Exception
    {
        return TinkJsonProtoKeysetFormat.parseKeyset(
                new String(Files.readAllBytes( Paths.get(filename)), UTF_8), InsecureSecretKeyAccess.get());
    }
}
class HybridSimple {

    private KeysetHandle privateKey;
    private KeysetHandle publicKey;


    public HybridSimple(KeysetHandle privateKeyIn, KeysetHandle publicKeyIn) throws Exception {
        privateKey = privateKeyIn;
        publicKey = publicKeyIn;
    }

    public KeysetHandle getPublicKey() {
        return publicKey;
    }

    public byte[] encrypt(KeysetHandle partnerPublicKey, String message, String metadata) throws Exception {

        HybridEncrypt encryptor = partnerPublicKey.getPrimitive(HybridEncrypt.class);

        // вернуть зашифрованное значение
        return encryptor.encrypt(message.getBytes(UTF_8), metadata.getBytes(UTF_8));
    }
    public String decrypt(byte[] ciphertext, String metadata) throws Exception {

        HybridDecrypt decryptor = privateKey.getPrimitive(HybridDecrypt.class);

        // вернуть расшифрованное значение
        return new String(decryptor.decrypt(ciphertext, metadata.getBytes(UTF_8)),UTF_8);
    }


}

    Асимметричный пример с использованием встроенных классов JCA/JCE¶

    Если использовать отдельную библиотеку категорически невозможно, можно использовать встроенные классы JCA/JCE, однако настоятельно рекомендуется привлечь эксперта по криптографии для проверки всего дизайна и кода, поскольку даже самая незначительная ошибка может серьёзно ослабить шифрование.

    Следующий фрагмент кода демонстрирует пример использования Elliptic Curve/Diffie Helman (ECDH) совместно с AES-GCM для шифрования/расшифрования данных между двумя сторонами без необходимости передавать симметричный ключ. Вместо этого стороны обмениваются открытыми ключами и могут использовать ECDH для генерации общего секрета, применяемого для симметричного шифрования.

    Обратите внимание, что этот пример кода использует класс AesGcmSimple из предыдущего раздела.

    Несколько ограничений и подводных камней этого кода:

    • В нём не учитываются ротация и управление ключами — это отдельная тема.
    • Код намеренно обеспечивает новый nonce для каждой операции шифрования, но им необходимо управлять как отдельным элементом данных наряду с шифртекстом.
    • Приватные ключи необходимо хранить в надёжном месте.
    • Код не учитывает валидацию открытых ключей перед использованием.
    • В целом отсутствует проверка подлинности между двумя сторонами.
    Нажмите, чтобы увидеть фрагмент кода "JCA/JCE hybrid encryption". 
    import java.nio.charset.StandardCharsets;
import java.security.SecureRandom;
import javax.crypto.spec.*;
import javax.crypto.*;
import java.util.*;
import java.security.*;
import java.security.spec.*;
import java.util.Arrays;

// ECDHSimpleTest
class Main {
    public static void main(String[] args) throws Exception {

        // Сгенерировать пару ключей ECC для Алисы
        var alice = new ECDHSimple();
        Key alicePublicKey = alice.getPublicKey();

        // Сгенерировать пару ключей ECC для Боба
        var bob = new ECDHSimple();
        Key bobPublicKey = bob.getPublicKey();

        // Эту генерацию ключевой пары следует периодически повторять, чтобы
        // получить новый общий секрет и избежать долгоживущего общего секрета.

        // Алиса шифрует сообщение для отправки Бобу
        String plaintext = "Hello"; //, Bob!";
        System.out.println("Secret being sent from Alice to Bob: " + plaintext);

        var retPair = alice.encrypt(bobPublicKey, plaintext);
        var nonce = retPair.getKey();
        var cipherText = retPair.getValue();

        System.out.println("Both cipherText and nonce being sent from Alice to Bob: " + Base64.getEncoder().encodeToString(cipherText) + " " + Base64.getEncoder().encodeToString(nonce));


        // Боб расшифровывает сообщение
        var decrypted = bob.decrypt(alicePublicKey, cipherText, nonce);
        System.out.println("Secret received by Bob from Alice: " + decrypted);
        System.out.println();

        // Боб шифрует сообщение для отправки Алисе
        String plaintext2 = "Hello"; //, Alice!";
        System.out.println("Secret being sent from Bob to Alice: " + plaintext2);

        var retPair2 = bob.encrypt(alicePublicKey, plaintext2);
        var nonce2 = retPair2.getKey();
        var cipherText2 = retPair2.getValue();
        System.out.println("Both cipherText2 and nonce2 being sent from Bob to Alice: " + Base64.getEncoder().encodeToString(cipherText2) + " " + Base64.getEncoder().encodeToString(nonce2));

        // Алиса расшифровывает сообщение
        var decrypted2 = alice.decrypt(bobPublicKey, cipherText2, nonce2);
        System.out.println("Secret received by Alice from Bob: " + decrypted2);
    }
}
class ECDHSimple {
    private KeyPair keyPair;

    public class AesKeyNonce {
        public SecretKey Key;
        public byte[] Nonce;
    }

    public ECDHSimple() throws Exception {
        KeyPairGenerator keyPairGenerator = KeyPairGenerator.getInstance("EC");
        ECGenParameterSpec ecSpec = new ECGenParameterSpec("secp256r1"); // Используется кривая secp256r1
        keyPairGenerator.initialize(ecSpec);
        keyPair = keyPairGenerator.generateKeyPair();
    }

    public Key getPublicKey() {
        return keyPair.getPublic();
    }

    public AbstractMap.SimpleEntry<byte[], byte[]> encrypt(Key partnerPublicKey, String message) throws Exception {

        // Сгенерировать AES-ключ и Nonce
        AesKeyNonce aesParams = generateAESParams(partnerPublicKey);

        // вернуть зашифрованное значение
        return new AbstractMap.SimpleEntry<>(
            aesParams.Nonce,
            AesGcmSimple.encrypt(message, aesParams.Nonce, aesParams.Key)
            );
    }
    public String decrypt(Key partnerPublicKey, byte[] ciphertext, byte[] nonce) throws Exception {

        // Сгенерировать AES-ключ и Nonce
        AesKeyNonce aesParams = generateAESParams(partnerPublicKey, nonce);

        // вернуть расшифрованное значение
        return AesGcmSimple.decrypt(ciphertext, aesParams.Nonce, aesParams.Key);
    }

    private AesKeyNonce generateAESParams(Key partnerPublicKey, byte[] nonce) throws Exception {

        // Вычислить секрет на основе приватного ключа этой стороны и открытого ключа другой стороны
        KeyAgreement keyAgreement = KeyAgreement.getInstance("ECDH");
        keyAgreement.init(keyPair.getPrivate());
        keyAgreement.doPhase(partnerPublicKey, true);
        byte[] secret = keyAgreement.generateSecret();

        AesKeyNonce aesKeyNonce = new AesKeyNonce();

        // Скопировать первые 32 байта как ключ
        byte[] key = Arrays.copyOfRange(secret, 0, (AesGcmSimple.KEY_SIZE / 8));
        aesKeyNonce.Key = new SecretKeySpec(key, 0, key.length, "AES");

        // Будет использован переданный nonce.
        aesKeyNonce.Nonce = nonce;
        return aesKeyNonce;

    }

    private AesKeyNonce generateAESParams(Key partnerPublicKey) throws Exception {

        // Nonce длиной 12 байт / 96 бит — этот размер всегда должен использоваться.
        // Крайне важно для AES-GCM использовать уникальный nonce для каждой криптографической операции.
        // Поэтому он не генерируется из общего секрета
        byte[] nonce = new byte[AesGcmSimple.IV_LENGTH];
        SecureRandom random = new SecureRandom();
        random.nextBytes(nonce);
        return generateAESParams(partnerPublicKey, nonce);

    }
}
