    Шпаргалка по Mass Assignment¶

    Введение¶

    Определение¶

    Фреймворки иногда позволяют разработчикам автоматически связывать параметры HTTP-запроса с переменными или объектами программного кода, чтобы упростить работу с фреймворком. Иногда это может причинить вред.

    Злоумышленники могут использовать эту возможность для создания новых параметров, которые разработчик никогда не предполагал, что в свою очередь создаёт или перезаписывает новые переменные или объекты в коде программы вопреки замыслу разработчика.

    Это называется уязвимостью Mass Assignment.

    Альтернативные названия¶

    В зависимости от языка/фреймворка эта уязвимость может иметь несколько альтернативных названий:

    • Mass Assignment: Ruby on Rails, NodeJS.
    • Autobinding: Spring MVC, ASP NET MVC.
    • Object injection: PHP.

    Пример¶

    Предположим, есть форма для редактирования информации об аккаунте пользователя:

    <form>
     <input name="userid" type="text">
     <input name="password" type="text">
     <input name="email" text="text">
     <input type="submit">
</form>

    Вот объект, с которым связывается форма:

    public class User {
   private String userid;
   private String password;
   private String email;
   private boolean isAdmin;

   //Геттеры и сеттеры
}

    Вот контроллер, обрабатывающий запрос:

    @RequestMapping(value = "/addUser", method = RequestMethod.POST)
public String submit(User user) {
   userService.add(user);
   return "successPage";
}

    Вот типичный запрос:

    POST /addUser
...
userid=bobbytables&password=hashedpass&email=bobby@tables.com

    А вот эксплойт, с помощью которого задаётся значение атрибута isAdmin экземпляра класса User:

    POST /addUser
...
userid=bobbytables&password=hashedpass&email=bobby@tables.com&isAdmin=true

    Возможность эксплуатации¶

    Эта функциональность становится уязвимой, когда:

    • Злоумышленник может угадать распространённые чувствительные поля.
    • Злоумышленник имеет доступ к исходному коду и может изучить модели на предмет чувствительных полей.
    • И объект с чувствительными полями имеет пустой конструктор.

    Случай с GitHub¶

    В 2012 году GitHub был взломан с использованием mass assignment. Пользователь смог загрузить свой публичный ключ в любую организацию и таким образом вносить любые последующие изменения в их репозитории. Публикация в блоге GitHub.

    Решения¶

    • Используйте список разрешённых (allow-list) для связываемых, нечувствительных полей.
    • Используйте список запрещённых (block-list) для несвязываемых, чувствительных полей.
    • Используйте Data Transfer Objects (DTO).

    Общие решения¶

    Архитектурный подход заключается в создании Data Transfer Objects и отказе от прямой привязки ввода к доменным объектам. В DTO включаются только те поля, которые предназначены для редактирования пользователем.

    public class UserRegistrationFormDTO {
 private String userid;
 private String password;
 private String email;

 //ПРИМЕЧАНИЕ: поле isAdmin отсутствует

 //Геттеры и сеттеры
}

public class UserController
{
    @InitBinder
    public void initBinder(WebDataBinder binder, WebRequest request)
    {
        binder.setAllowedFields(["userid","password","email"]);
    }
...
}

    NodeJS + Mongoose¶

    Allow-listing (список разрешённых)¶

    var UserSchema = new mongoose.Schema({
    userid: String,
    password: String,
    email : String,
    isAdmin : Boolean,
});

UserSchema.statics = {
    User.userCreateSafeFields: ['userid', 'password', 'email']
};

var User = mongoose.model('User', UserSchema);

_ = require('underscore');
var user = new User(_.pick(req.body, User.userCreateSafeFields));

    Смотрите документацию здесь.

    Block-listing (список запрещённых)¶

    var massAssign = require('mongoose-mass-assign');

var UserSchema = new mongoose.Schema({
    userid: String,
    password: String,
    email : String,
    isAdmin : { type: Boolean, protect: true, default: false }
});

UserSchema.plugin(massAssign);

var User = mongoose.model('User', UserSchema);

/** Статический метод, полезен при создании **/
var user = User.massAssign(req.body);

/** Метод экземпляра, полезен при обновлении**/
var user = new User;
user.massAssign(req.body);

/** Статический метод massUpdate **/
var input = { userid: 'bhelx', isAdmin: 'true' };
User.update({ '_id': someId }, { $set: User.massUpdate(input) }, console.log);
